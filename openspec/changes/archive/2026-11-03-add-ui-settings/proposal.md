## Why

Набор камер мониторинга и порог узнавания сейчас задаются только переменными
окружения, и чтобы их поменять, нужно пересоздавать контейнер. На реальной
установке это уже привело к поломке: в `ROSDOMOFON_MONITOR_CAMERAS` осталось
значение `1001` из примера в README, мониторинг тихо оказался пустым, и лица
распознавались только пока открыт UI. Ошибку видно только в логе. Порог узнавания
приходится подбирать на месте, глядя на журнал, и перезапуск на каждой итерации
неудобен.

## What Changes

- Новая вкладка «Настройки» в веб-интерфейсе:
  - список камер аккаунта с отметкой «мониторить круглосуточно»; там же видно, работает
    ли поток камеры и какая у неё последняя ошибка;
  - поле порога узнавания (косинусное сходство, 0–1) с подсказкой, на что он влияет;
  - кнопки «По умолчанию», чтобы вернуть значение из переменной окружения.
- Настройки хранятся в базе (`data/faces.db`, таблица `settings`) и переживают
  перезапуск. Значение из UI важнее переменной окружения, а переменные
  `ROSDOMOFON_MONITOR_CAMERAS` и `ROSDOMOFON_MATCH_THRESHOLD` становятся значениями
  по умолчанию.
- Изменения применяются без перезапуска: камеры, добавленные в набор, сразу начинают
  мониториться; исключённые останавливаются, если их никто не смотрит; новый порог
  действует со следующего распознавания.
- API: `GET /api/settings` и `PUT /api/settings` (частичное обновление, `null` —
  сброс к значению по умолчанию).
- Камеры из набора по умолчанию, которых нет в аккаунте, показываются в UI с
  предупреждением, а не только в логе.
- README: пример `docker run` без `ROSDOMOFON_MONITOR_CAMERAS=1001`, описание
  вкладки «Настройки» и того, как значения из UI соотносятся с переменными окружения.

Не входит: другие параметры (качество, трекинг, сроки хранения), автоматический
повтор запуска мониторинга при сбое на старте.

### Modified Capabilities
- `camera-monitoring`: набор камер мониторинга задаётся в интерфейсе (env — значение
  по умолчанию) и меняется без перезапуска; камеры из набора, которых нет в аккаунте,
  видны в интерфейсе.
- `face-recognition`: порог узнавания задаётся в интерфейсе (env — значение по
  умолчанию) и применяется без перезапуска.

## Impact

- `app/store.py` — чтение и запись настроек `monitor_cameras` и `match_threshold` в
  таблице `settings` (с кэшем в памяти).
- `app/recognizer.py` — порог берётся из хранилища, а не из `config`.
- `app/stream.py` — `WorkerRegistry` применяет новый набор камер мониторинга на лету.
- `app/main.py` — эндпоинты `/api/settings`.
- `app/static/index.html` — вкладка «Настройки».
- Тесты: `tests/test_store.py`, `tests/test_api.py`, `tests/test_tracking.py`/новые
  тесты реестра воркеров.
- `README.md`. Новых зависимостей нет, миграция схемы не нужна (таблица `settings`
  уже есть).
