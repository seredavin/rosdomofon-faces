## Context

FastAPI-приложение (`app/main.py`) с ванильным UI (`app/static/index.html`).
Эндпоинты `/api/auth/*` и экран «Вход» в UI — это вход в **аккаунт Росдомофона**
(SMS/refresh_token), к входу в интерфейс отношения не имеют, и их 401 UI уже
обрабатывает показом формы SMS. Видео отдаётся как MJPEG в `<img>`, снимки — как
`<img src>`: заголовки авторизации к ним не добавить, только cookie. Docker
healthcheck дёргает `/api/auth/status`. Требования — `specs/ui-access/spec.md`.

## Goals / Non-Goals

**Goals:**
- Один пароль из окружения, ноль новых зависимостей, без хранилища сессий.
- Защита «по умолчанию»: новый эндпоинт закрыт, пока его явно не сделали публичным.

**Non-Goals:**
- Несколько пользователей, роли, смена пароля из UI, 2FA, OAuth.
- Собственный TLS: HTTPS обеспечивает reverse proxy (Caddy/nginx/Traefik).
- Защита от распределённого подбора с множества адресов (см. риски).

## Decisions

### Пароль — `ROSDOMOFON_UI_PASSWORD` в открытом виде
Сравнение через `hmac.compare_digest` от SHA-256 обоих значений (постоянное время,
независимо от длины). Хеш (bcrypt/argon2) в переменной не храним: пароль и так
лежит в окружении процесса рядом с токенами Росдомофона в `data/`, а хеш потребовал
бы зависимости и утилиты для генерации. Альтернатива — файл с паролем в `data/`
или первичная настройка из UI — отклонена: сложнее, а окно «первый, кто открыл,
задаёт пароль» опасно для публичного сервиса.

### Пароль не задан — авторизация выключена
Сохраняет нынешнее поведение для запуска на localhost и существующих контейнеров
(`-p 127.0.0.1:8000:8000`). При старте — `WARNING` в логе. Альтернатива —
отказываться стартовать на не-loopback адресе без пароля — не работает в Docker,
где внутри контейнера всегда `0.0.0.0`.

### Сессия — stateless подписанная cookie
Значение: `<expires>.<hmac>`, где `hmac = HMAC-SHA256(key, expires)`, а
`key = HMAC-SHA256(secret, password)`. `secret` — 32 случайных байта в
`data/session_secret` (создаётся при первом старте, права 0600), поэтому сессии
переживают перезапуск. Пароль входит в ключ — его смена инвалидирует все сессии.
Cookie `rdf_session`: `HttpOnly`, `SameSite=Strict`, `Path=/`, `Max-Age=30 дней`,
`Secure` — если запрос пришёл по HTTPS. Выход просто удаляет cookie; отозвать
украденную cookie можно сменой пароля (или удалением `session_secret`).
Альтернатива — серверное хранилище сессий в SQLite — даёт отзыв отдельных сессий,
но для одного пользователя это лишнее.

### Проверка — чистый ASGI-middleware с белым списком
Middleware перед всеми маршрутами; публичны только `GET /login`,
`POST /api/session/login`, `POST /api/session/logout`, `GET /api/session`,
`GET /api/health`. Без сессии: путь под `/api/` → 401
`{"detail": "Нужен вход в интерфейс", "code": "ui_login_required"}`; остальное →
303 на `/login`. Чистый ASGI, а не `BaseHTTPMiddleware`, — чтобы не оборачивать
долгоживущий MJPEG-поток. Альтернатива — глобальная FastAPI-зависимость —
отклонена: исключения для публичных маршрутов размазываются по коду.

### Эндпоинты `/api/session/*`, а не `/api/auth/*`
`/api/auth/*` уже занят входом в Росдомофон; переименование сломало бы UI и
сценарии пользователей. `GET /api/session` → `{"enabled": bool, "authenticated": bool}`
— UI по нему решает, показывать ли кнопку «Выйти из интерфейса».
`POST /api/session/login` принимает JSON `{"password": "..."}` (JSON +
`SameSite=Strict` закрывают CSRF без токенов).

### UI
Отдельная `app/static/login.html` (форма пароля, `fetch` на login, при успехе —
`location = "/"`), чтобы основной интерфейс не грузился без входа. В `index.html`
функция `api()` при `code === "ui_login_required"` делает `location = "/login"`;
прежняя обработка 401 (форма SMS Росдомофона) остаётся для остальных 401.
Кнопка «Выйти из интерфейса» отдельно от существующей «Выйти» (выход из аккаунта
Росдомофона, останавливает мониторинг) — подписи различаются, чтобы не перепутать.

### Лимит попыток — в памяти по IP
`dict[ip, deque[timestamp]]` неудач за 15 минут, порог 5, проверка до сравнения
пароля; успех очищает запись адреса; старые записи вычищаются при обращении.
Сбрасывается при перезапуске — приемлемо. IP клиента за reverse proxy — из
`X-Forwarded-For` через `uvicorn --proxy-headers`; доверенные адреса прокси —
`ROSDOMOFON_FORWARDED_ALLOW_IPS` (по умолчанию `127.0.0.1`, как в uvicorn),
пробрасывается в `uvicorn.run(forwarded_allow_ips=...)`. Это же даёт верную схему
(https) для флага `Secure`.

### Healthcheck — `GET /api/health` → `{"ok": true}`
Публичный и без данных; Dockerfile переходит на него.

## Risks / Trade-offs

- [Слабый пароль при публикации в интернет] → README требует длинный случайный
  пароль (`openssl rand -base64 24`); лимит попыток замедляет подбор с одного адреса.
- [Распределённый подбор с многих IP обходит лимит по адресу] → глобальный лимит не
  вводим, он позволил бы заблокировать владельца; полагаемся на длину пароля.
- [Неверно настроенные доверенные прокси: все клиенты с IP прокси] → лимит станет
  общим (можно заблокировать себя на 15 минут), `Secure` не выставится. README
  описывает `ROSDOMOFON_FORWARDED_ALLOW_IPS`; без HTTPS публиковать нельзя.
- [Украденная cookie действует до 30 дней] → `HttpOnly` + `Secure`; отзыв — смена
  пароля.
- [Пароль в открытом виде в окружении] → тот же уровень доступа, что и к токенам
  Росдомофона в `data/`; принято.

## Migration Plan

Без пароля поведение не меняется. Для публикации: задать
`ROSDOMOFON_UI_PASSWORD`, поставить reverse proxy с HTTPS, при необходимости
`ROSDOMOFON_FORWARDED_ALLOW_IPS`. Откат — убрать переменную (авторизация
выключится) или откатить образ.
