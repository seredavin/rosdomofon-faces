## Why

У сервиса нет своей авторизации, поэтому он слушает только localhost: любой, кто
достучится до порта, видит камеры подъезда, базу лиц соседей (биометрия) и может
открыть дверь. Чтобы опубликовать UI в интернет (за reverse proxy с HTTPS), нужен
вход по паролю — простой, на одного владельца, без ролей.

## What Changes

- Вход в веб-интерфейс по одному паролю, который задаётся переменной окружения
  `ROSDOMOFON_UI_PASSWORD`. Пользователь один, ролей нет: вошедший может всё.
- Сессия в подписанной cookie (`HttpOnly`, `SameSite=Strict`, `Secure` при HTTPS),
  срок жизни 30 дней; выход сбрасывает cookie; смена пароля завершает все сессии.
- Все страницы и `/api/*` (включая MJPEG и снимки лиц) требуют сессию; без неё —
  401 для API и переход на страницу входа для HTML. Открыты только страница входа,
  эндпоинты входа/выхода и `/api/health` для healthcheck.
- Защита от подбора: ограничение частоты неудачных попыток входа.
- Пароль не задан — авторизация выключена, как сейчас, с предупреждением в логе
  при старте (обратная совместимость для запуска на localhost).
- Healthcheck в Dockerfile переходит на открытый `/api/health`.
- README: как задать пароль и опубликовать UI за reverse proxy с HTTPS.

## Impact

- `app/main.py` — middleware проверки сессии, эндпоинты `/api/session/*`, `/api/health`.
- Новый модуль `app/session.py` — подпись/проверка cookie, лимит попыток.
- `app/config.py` — `UI_PASSWORD`, срок сессии, файл секрета `data/session_secret`.
- `app/static/` — страница входа `login.html`, кнопка «Выйти из UI» в `index.html`.
- `Dockerfile` (healthcheck), `README.md`, тесты `tests/test_session.py`.
- Новых зависимостей нет (подпись — `hmac`/`hashlib` из стандартной библиотеки).
- Существующие `/api/auth/*` (вход в аккаунт Росдомофона) не переименовываются, но
  становятся доступны только после входа в UI.
