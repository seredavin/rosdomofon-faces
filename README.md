# Росдомофон: распознавание лиц

Веб-сервис для камер домофона Росдомофон: вход в аккаунт (SMS или refresh_token),
просмотр камер в браузере, поиск и распознавание лиц (YuNet + SFace / OpenCV),
галерея незнакомых лиц, база знакомых людей и журнал появлений у двери.

## Docker

Образ собирается в GitHub Actions для `linux/amd64` и `linux/arm64` и
публикуется в GHCR: `latest` — из `main`, `sha-…` — на каждый коммит, `X.Y.Z` —
по тегу `vX.Y.Z`. Модели и шрифт уже внутри образа.

```bash
docker run -d --name rosdomofon-faces --restart unless-stopped \
  -p 127.0.0.1:8000:8000 \
  -v rosdomofon-faces-data:/app/data \
  ghcr.io/seredavin/rosdomofon-faces:latest
```

Порт публикуется только на `127.0.0.1`: без пароля интерфейс открыт любому, а
через него можно открыть дверь подъезда. Как открыть доступ из интернета — см.
«Публикация в интернет». Данные (токены, база лиц) — в томе `/app/data`.

## Запуск без Docker

```bash
python3.13 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m app            # http://127.0.0.1:8000
```

При первом запуске в `models/` скачиваются модели YuNet и SFace и шрифт Noto Sans
(с проверкой SHA-256).

Сервер по умолчанию слушает только localhost: без `ROSDOMOFON_UI_PASSWORD`
интерфейс открыт без пароля, а через него доступны камеры, база лиц и дверь.

## Публикация в интернет

1. Задайте длинный случайный пароль интерфейса:
   `ROSDOMOFON_UI_PASSWORD="$(openssl rand -base64 24)"`. Пользователь один,
   ролей нет: кто вошёл, может всё, включая открытие двери.
2. Поставьте перед сервисом reverse proxy с HTTPS — по HTTP пароль и cookie
   сессии передаются открытым текстом. Пример `Caddyfile` (сертификат Let's
   Encrypt Caddy получит сам):

   ```
   faces.example.com {
       reverse_proxy 127.0.0.1:8000
   }
   ```

3. Если прокси обращается к сервису не с `127.0.0.1` (например, из соседнего
   Docker-контейнера), укажите его адрес в `ROSDOMOFON_FORWARDED_ALLOW_IPS` —
   иначе сервис не увидит настоящий адрес клиента (лимит попыток входа станет
   общим на всех) и схему HTTPS (cookie без флага `Secure`).

Сессия живёт 30 дней. После 5 неудачных попыток входа за 15 минут адрес
блокируется до конца окна. Выйти на всех устройствах — сменить пароль и
перезапустить сервис.

## Как пользоваться

1. **Видео** — камера с рамками: зелёная с именем — знакомый, оранжевая
   «Неизвестный», серая — ещё определяется (или лицо слишком мелкое/повёрнутое).
2. **Незнакомые** — каждое появление незнакомого человека даёт карточку с лучшим
   кадром лица. Выберите человека или введите новое имя — лицо станет образцом,
   и дальше человек распознаётся без перезапуска.
3. **Люди** — образцы каждого человека, переименование и удаление.
   Для надёжного распознавания нужно 5–10 образцов в разных условиях (день,
   вечер, в шапке и без).
4. **Журнал** — кто и когда подходил, с фильтрами по камере, человеку, времени
   и «только с открытием».
5. **Двери** — автоматическое открытие двери для знакомых (см. ниже).
6. **Настройки** — какие камеры мониторить круглосуточно (с состоянием потока
   каждой камеры) и порог узнавания. Применяется сразу, без перезапуска.

Камеры мониторинга анализируются круглосуточно, даже без открытой страницы
(~1 ядро CPU и 1–2 Мбит/с на камеру). Без зрителей кадры не кодируются в JPEG.
Остальные камеры анализируются, только пока открыто их видео.

## Открытие двери

Дверь открывается автоматически, когда на камере узнан человек, если
одновременно:

- у человека включено «может открывать дверь» (вкладка «Люди», по умолчанию выкл.);
- камера привязана к двери (вкладка «Двери», по умолчанию не привязана);
- режим не «выключено».

Режимы (вкладка «Двери»): **выключено**; **только журнал** (по умолчанию) — в
журнал пишется «открыл бы», дверь не трогается; **открывать** — команда
`activate_key` в Росдомофон. Не больше одного открытия за появление и не чаще
раза в 30 секунд на дверь. Результат («дверь открыта», «открыл бы», «ошибка
открытия») виден у события в журнале.

**Риски.** Распознавание не защищено от подделки: фото жильца на телефоне может
открыть дверь. Порог сходства общий с распознаванием, возможны ложные
узнавания. Дверь подъезда общая — ошибка затрагивает всех соседей. Перед
включением «открывать» погоняйте неделю в режиме «только журнал» и, если
«открыл бы» срабатывает на чужих, поднимите порог узнавания (вкладка «Настройки»).

## Настройки

Набор камер мониторинга и порог узнавания задаются на вкладке «Настройки» и
хранятся в `faces.db`. Значение из интерфейса важнее переменной окружения;
переменная — значение по умолчанию, к которому возвращает кнопка «По умолчанию».

Переменные окружения:

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `ROSDOMOFON_UI_PASSWORD` | пусто | пароль входа в интерфейс; пусто — интерфейс открыт без пароля |
| `ROSDOMOFON_FORWARDED_ALLOW_IPS` | `127.0.0.1` | адреса reverse proxy, которым верим в `X-Forwarded-For`/`-Proto` (через запятую, `*` — всем) |
| `ROSDOMOFON_MONITOR_CAMERAS` | все камеры | id камер для круглосуточного анализа через запятую (по умолчанию для вкладки «Настройки») |
| `ROSDOMOFON_MATCH_THRESHOLD` | `0.363` | порог косинусного сходства; выше — меньше ложных узнаваний, больше «Неизвестный» (по умолчанию для вкладки «Настройки») |
| `ROSDOMOFON_MIN_FACE_SIZE` | `40` | минимальный размер лица (px) для распознавания |
| `ROSDOMOFON_MIN_SHARPNESS` | `30` | минимальная резкость лица (дисперсия лапласиана) |
| `ROSDOMOFON_TRACK_TIMEOUT` | `2` | через сколько секунд без лица появление завершается |
| `ROSDOMOFON_UNKNOWN_RETENTION_DAYS` | `7` | срок хранения событий и снимков незнакомых |
| `ROSDOMOFON_KNOWN_RETENTION_DAYS` | `30` | срок хранения событий знакомых |
| `ROSDOMOFON_DATA_DIR` | `data/` | каталог данных |

## Данные

Всё хранится локально в `data/` (не коммитится):

- `token.json` — токены Росдомофона (права 0600);
- `session_secret` — ключ подписи сессий интерфейса (права 0600; удаление
  завершает все сессии);
- `faces.db` — SQLite: люди, образцы (векторы лиц), события, настройки из интерфейса;
- `faces/events/`, `faces/samples/` — снимки лиц.

Векторы лиц — биометрия. Камеры смотрят на общий подъезд, поэтому храним минимум:
векторы незнакомых живут только в карточках галереи и удаляются вместе с ними
через 7 дней; у событий знакомых векторов нет; образцы есть только у людей,
которых вы добавили сами. Очистка — при старте и раз в час.

## API

Без сессии (если задан пароль) все пути, кроме `/login`, `/api/session*` и
`/api/health`, отвечают 401 `{"code": "ui_login_required"}`, а страницы —
переходом на `/login`.

| Метод | Путь | Что делает |
|---|---|---|
| GET  | `/api/health` | проверка работоспособности (без входа) |
| GET  | `/api/session` | `{enabled, authenticated}` — включён ли вход и выполнен ли он |
| POST | `/api/session/login` `{password}` | войти в интерфейс (cookie сессии); 401 — неверный пароль, 429 — слишком много попыток |
| POST | `/api/session/logout` | выйти из интерфейса |
| GET  | `/api/auth/status` | выполнен ли вход в аккаунт Росдомофона |
| POST | `/api/auth/sms` `{phone}` | отправить SMS-код |
| POST | `/api/auth/code` `{phone, code}` | войти по коду (запускает мониторинг) |
| POST | `/api/auth/refresh-token` `{refresh_token}` | войти по refresh_token (запускает мониторинг) |
| POST | `/api/auth/logout` | выйти, остановить мониторинг, удалить токены |
| GET  | `/api/cameras` | список камер |
| GET  | `/api/status` | состояние воркеров камер |
| GET  | `/api/cameras/{id}/mjpeg` | видео с рамками и подписями (MJPEG) |
| GET  | `/api/cameras/{id}/faces` | лица в кадре: рамка, `track_id`, `status`, `person` |
| GET  | `/api/events` | журнал; фильтры `camera_id`, `person_id`, `unknown`, `gallery`, `unlocked`, `since`, `until`; страницы — `before_id`, `limit` → `{items, next_before_id}` |
| GET  | `/api/events/{id}/image` | снимок лица события |
| DELETE | `/api/events/{id}` | удалить событие (карточку) |
| POST | `/api/events/{id}/assign` `{person_id}` или `{name}` | подписать карточку незнакомого |
| GET/POST | `/api/persons` | список людей с образцами / создать `{name}` |
| PATCH/DELETE | `/api/persons/{id}` | изменить `{name, can_unlock}` / удалить с образцами |
| GET  | `/api/samples/{id}/image` | снимок образца |
| GET  | `/api/doors` | двери (ключи) аккаунта |
| GET/PUT | `/api/unlock` | режим открытия и привязки камер `{mode, bindings: {camera_id: door_id \| null}}` |
| DELETE | `/api/samples/{id}` | удалить образец |
| GET/PUT | `/api/settings` | камеры мониторинга и порог `{monitor_cameras, match_threshold}` (+ `*_default`, `*_source`); PUT — частично, `null` — сброс к значению из окружения |

## Устройство

- `app/rosdomofon.py` — клиент API Росдомофона, автообновление токена.
- `app/session.py` — вход в интерфейс: подписанная cookie, лимит попыток, middleware.
- `app/stream.py` — воркер на камеру: PyAV читает HLS с `Authorization: Bearer`
  в отдельном потоке, кадры идут в темпе PTS. Постоянные воркеры — для камер
  мониторинга, по требованию — для остальных (стоп через 30 с без зрителей);
  набор камер мониторинга пересчитывается на лету при смене настроек.
- `app/pipeline.py` — конвейер кадра: детекция (≤10 раз/с) → трекинг →
  фильтр качества → распознавание (≤3 раз/с на появление) → голосование →
  событие по завершении появления.
- `app/detector.py` (YuNet), `app/recognizer.py` (SFace), `app/quality.py`,
  `app/tracker.py`, `app/overlay.py` (рамки и подписи кириллицей через Pillow),
  `app/store.py` (SQLite и снимки), `app/unlock.py` (открытие двери).
- Спецификации и решения — `openspec/`.

## Разработка

```bash
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/pytest
openspec validate --all --strict
```

На macOS при старте печатается предупреждение `objc: Class AVFFrameReceiver is
implemented in both ...` — OpenCV и PyAV везут свои копии ffmpeg. Дублируются
только классы захвата с веб-камеры, которые не используются; безвредно.
